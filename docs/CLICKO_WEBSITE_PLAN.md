## คำตัดสินสถาปัตยกรรมล่าสุด — 9 พฤศจิกายน 2026

ข้อกำหนดล่าสุด: ผู้ขายรับซื้อขายกับลูกค้าผ่าน Facebook ส่วนตัวเท่านั้น เพจ Clicko.gg ใช้แสดงแบรนด์และข่าวสาร ปุ่มซื้อและสอบถามสินค้าต้องไปยังบัญชีส่วนตัว เป้าหมายคือเปิด Messenger ของผู้ขายโดยตรงพร้อมข้อมูลสินค้าที่เลือก แต่ยังไม่ได้ยืนยันลิงก์แชทและการแนบข้อความอัตโนมัติของบัญชีนี้ จึงใช้ข้อความสรุปที่คัดลอกได้เป็นวิธีส่งต่อรายการ และไม่ใช้ระบบแชทของเพจมาแทนช่องทางส่วนตัว

## 1. ขอบเขตที่ยืนยันแล้ว

เว็บไซต์ช่วยให้ลูกค้าค้นหา ดูสเปก เลือกรุ่นและจำนวนสินค้า ก่อนเปิด Facebook ที่ร้านระบุเพื่อตกลงซื้อขาย

- ใช้ Facebook ส่วนตัวของผู้ขายเป็นช่องทางซื้อขายเท่านั้น เมื่อยืนยันลิงก์ Messenger ของบัญชีนี้แล้วให้ใช้เปิดแชทตรง โดยยังมีลิงก์โปรไฟล์เป็นทางสำรอง
- การยืนยันสินค้า ราคา ค่าส่ง ชำระเงิน ที่อยู่ และติดตามพัสดุทำผ่านการพูดคุยกับร้าน
- ปุ่มบนเว็บพาลูกค้าไปยัง Facebook ส่วนลูกค้าเป็นผู้ส่งข้อความเอง
- การเลือกสินค้าบนเว็บยังไม่ถือว่าเป็นคำสั่งซื้อหรือการจองสินค้า
- แสดงลิงก์เพจ Clicko.gg แยกเป็น “ติดตามเพจ Clicko” และไม่ใช้เป็นปลายทางของปุ่มซื้อหรือสอบถามสินค้า
- ขอบเขตนี้แทนแผนเดิมที่ให้ checkout และชำระเงินบนเว็บเป็นส่วนของเวอร์ชันแรก

## 2. เส้นทางใช้งานหลัก

### 2.1 ลูกค้าสนใจสินค้าหนึ่งรายการ

1. เปิดหน้าสินค้า
2. เลือก SKU เช่น สี ความจุ หรือรูปแบบการเชื่อมต่อ และระบุจำนวน
3. กด “ติดต่อซื้อกับผู้ขาย”
4. แสดงสรุปสินค้าที่เลือก พร้อมปุ่ม “คัดลอกรายละเอียดสินค้า” และปุ่มเปิดช่องทางของผู้ขาย
5. ลูกค้าคัดลอกข้อมูล แล้วกด “เปิด Messenger ผู้ขาย” เมื่อมีลิงก์แชทที่ยืนยันแล้ว ระหว่างที่ยังไม่ยืนยันให้ใช้ “เปิด Facebook ผู้ขาย” ไปยังโปรไฟล์ส่วนตัว
6. ลูกค้าเริ่มติดต่อและวางข้อความเอง จากนั้นร้านตรวจสินค้าและตกลงรายละเอียด

ต้องมีลิงก์ติดต่อ Facebook ส่วนตัวของผู้ขายที่กดได้โดยตรงในหน้าสินค้าและหน้าติดต่อด้วย เพื่อให้ลูกค้าที่ต้องการสอบถามทันทีไม่ถูกบังคับให้ทำรายการหลายขั้น แยกลิงก์ติดตามเพจออกจากลิงก์ซื้อให้เห็นชัด

### 2.2 ลูกค้าสนใจหลายรายการ

1. กด “เพิ่มในรายการที่สนใจ” จากหน้าสินค้าหรือรายการสินค้า
2. เปิดหน้าสรุปรายการ
3. ตรวจ SKU จำนวน และยอดรวมสินค้าเบื้องต้น
4. กด “คัดลอกรายการสินค้า”
5. กด “เปิด Messenger ผู้ขาย” เมื่อยืนยันลิงก์แชทแล้ว หรือใช้ “เปิด Facebook ผู้ขาย” เป็นทางสำรอง
6. ส่งข้อความที่คัดลอกไว้ให้ร้านตรวจสอบและตกลงซื้อขาย

### 2.3 ข้อความกำกับที่ลูกค้าควรเห็น

> เลือกสินค้าแล้วคัดลอกรายการไปส่งให้ผู้ขายทาง Facebook ส่วนตัว เพื่อยืนยันราคา สินค้าคงเหลือ และค่าจัดส่ง

> รายการนี้ยังไม่ใช่คำสั่งซื้อ และยังไม่มีการจองสินค้า

> เมื่อเปิดแชทแล้ว กรุณาวางรายการและส่งข้อความหาผู้ขายด้วยตนเอง

> ติดตามข่าวสารได้ที่เพจ Clicko ส่วนการซื้อขายให้ติดต่อ Facebook ส่วนตัวของผู้ขาย

ไม่แสดงข้อความว่า “สั่งซื้อสำเร็จ” “ชำระเงินสำเร็จ” หรือ “ส่งข้อความแล้ว” จากการกดลิงก์เพียงอย่างเดียว

### 3.2 ลำดับหน้าแรก

1. โลโก้ ช่องค้นหา และเมนู
2. แบนเนอร์หลักพร้อมปุ่มไปดูสินค้า
3. หมวดสินค้ายอดนิยม
4. สินค้าแนะนำหรือขายดีที่ร้านเลือก
5. สินค้ามาใหม่
6. คอมประกอบหรือชุดสินค้าของร้าน หากมี
7. คำอธิบายวิธีซื้อสั้น ๆ: เลือกสินค้า → คัดลอก → ติดต่อ Facebook
8. ข้อมูลประกันและบริการตามที่ร้านให้บริการจริง
9. ข้อมูลติดต่อและส่วนท้าย

### 3.3 รายการสินค้าและตัวกรอง

- ค้นหาจากชื่อ รุ่น แบรนด์ และ SKU
- กรองหมวด แบรนด์ ช่วงราคา และสถานะสินค้า
- ตัวกรองสเปกเปลี่ยนตามหมวด
- เงื่อนไขค้นหาอยู่ใน URL เพื่อแชร์ลิงก์ได้
- การ์ดสินค้าแสดงรูป ชื่อรุ่น ราคา และสถานะสินค้า
- หากไม่มีราคายืนยัน ให้แสดง “สอบถามราคา” และไม่คำนวณรายการนั้นเป็นศูนย์บาท
- มีกรณีไม่พบสินค้า กำลังโหลด และโหลดไม่สำเร็จ
- เริ่มจากการค้นหาในฐานข้อมูล ประเมินระบบค้นหาแยกเมื่อมีความจำเป็น

### 3.4 รายละเอียดสินค้า

- รูปหลายมุมและคำอธิบายรูป
- ชื่อรุ่น แบรนด์ หมวด และรหัส SKU
- ตัวเลือกที่มีขายจริง เช่น สีหรือความจุ
- ราคาหรือ “สอบถามราคา” พร้อมวันที่ปรับปรุงข้อมูลหากเป็นประโยชน์
- สถานะพร้อมขาย สินค้าหมด หรือสอบถามก่อนสั่ง
- ตารางสเปกและรายละเอียดประกัน
- ปุ่ม “เพิ่มในรายการที่สนใจ”

### 5.3 การเก็บรายการฝั่งลูกค้า

- เก็บ SKU และจำนวนใน localStorage เพื่อให้กลับมาดูต่อบนเบราว์เซอร์เดิมได้
- โหลดชื่อ ราคา สถานะ และตัวเลือกจากข้อมูลสินค้าปัจจุบันอีกครั้งก่อนสร้างข้อความ
- ถ้าสินค้าถูกซ่อน หมด หรือเปลี่ยนราคา ให้แสดงให้ลูกค้ารับทราบ
- หาก localStorage ใช้ไม่ได้ ให้ยังเลือกสินค้าได้ในหน้านั้น และแจ้งว่าอาจไม่บันทึกข้ามการเปิดเว็บ
- มีปุ่มล้างรายการ และตรวจรูปแบบข้อมูลที่อ่านกลับมาจาก localStorage
- ข้อมูลไม่ซิงก์ข้ามอุปกรณ์ และอาจหายเมื่อลูกค้าล้างข้อมูลเบราว์เซอร์
- ไม่เก็บที่อยู่ เบอร์โทร สลิป หรือรายละเอียดชำระเงินในรายการนี้
- ไม่ล้างรายการอัตโนมัติเพียงเพราะลูกค้ากดเปิด Facebook

## 6. ช่องทางซื้อขายส่วนตัวและเพจแบรนด์

### 6.1 การตั้งค่าช่องทาง

| ค่า | ค่าเริ่มต้น | หน้าที่ |
| --- | --- | --- |
| `primary_sales_channel` | `facebook_profile` | ช่องทางซื้อขายส่วนตัวเท่านั้น |
| `facebook_profile_url` | `https://www.facebook.com/sippavit.gomarn` | โปรไฟล์ผู้ขายและทางสำรองเมื่อเปิดแชทตรงไม่ได้ |
| `facebook_page_url` | `https://www.facebook.com/Clicko.gg/` | เพจแบรนด์ ใช้ติดตามข่าวสาร |
| `seller_messenger_url` | `null` | ลิงก์ Messenger ส่วนตัว รอยืนยันและทดสอบก่อนใช้งาน |
| `page_link_label` | `ติดตามเพจ Clicko` | ข้อความลิงก์เพจ แยกจากปุ่มซื้อ |
| `sales_button_label` | `ติดต่อซื้อกับผู้ขาย` | ข้อความปุ่มหลัก |
| `sales_message_template` | ข้อความสรุปสินค้า | แก้ข้อความได้จากจุดเดียว |

- รวมการเลือก URL ปลายทางซื้อขายไว้ในส่วนกลาง โดยใช้ `seller_messenger_url` เมื่อผ่านการทดสอบแล้ว มิฉะนั้นใช้ `facebook_profile_url`
- ในระยะแรกให้เจ้าของร้านแก้ช่องทางผ่านการตั้งค่า แยกจากสิทธิ์จัดการสินค้า
- ตรวจ URL ก่อนบันทึก ให้เป็น HTTPS และเป็นโดเมน Facebook ที่อนุญาตตามรูปแบบช่องทาง
- การแก้ URL เพจมีผลเฉพาะลิงก์ติดตามแบรนด์ ไม่เปลี่ยนปลายทางปุ่มซื้อ
- ภายใต้ขอบเขตปัจจุบัน ไม่แสดงตัวเลือกให้ใช้เพจเป็นช่องทางซื้อขาย
- ไม่ส่งลูกค้าไปยังแชทเพจอัตโนมัติ แม้ลิงก์แชทส่วนตัวไม่พร้อมใช้งาน
- ไม่สร้าง URL Messenger จากชื่อโปรไฟล์โดยคาดเดา

### 6.2 พฤติกรรมของปุ่ม

- ปุ่มซื้อใช้ลิงก์บัญชีส่วนตัวของผู้ขาย ส่วนลิงก์ติดตามใช้ URL เพจ Clicko.gg และระบุวัตถุประสงค์ให้ตรงกัน
- เสนอเปิดแท็บใหม่เพื่อคงรายการบนเว็บไว้ พร้อมตั้งค่า `rel="noopener noreferrer"`
- แยกปุ่มคัดลอกกับปุ่มเปิด Facebook เพื่อให้ลูกค้าทำต่อได้แม้คัดลอกไม่สำเร็จ
- ปุ่มคัดลอกต้องทำจากการกดของลูกค้า และแสดงข้อความว่าสำเร็จเมื่อคัดลอกสำเร็จจริง
- หาก Clipboard API ใช้ไม่ได้หรือถูกปฏิเสธ ให้แสดงข้อความที่เลือกคัดลอกเองได้
- ให้การเปิด Facebook เกิดจากการกดลิงก์โดยตรง ไม่ผูกกับผลของงาน async ที่อาจทำให้เปิดแท็บไม่ได้
- ไม่บังคับให้ติดตั้งแอป Messenger เพื่อดูรายการสินค้าบนเว็บ

### 6.3 ขอบเขตที่ไม่ควรรับรอง

- การเปิด URL โปรไฟล์ไม่ถือว่ามีการส่งข้อความหรือส่งรายการสินค้าแล้ว
- รูปแบบแสดงผลและการเข้าถึงโปรไฟล์ขึ้นกับ Facebook บัญชีที่เข้าสู่ระบบ และอุปกรณ์ ต้องทดสอบกับร้านจริง
- ยังไม่ได้ยืนยันว่าลิงก์นี้เปิดหน้าสนทนาได้โดยตรง
- ไม่รับรองการเติมข้อความในแชทอัตโนมัติจากลิงก์โปรไฟล์นี้
- ขอบเขตปัจจุบันเป็นการเปิดลิงก์และให้คัดลอกข้อความ ไม่ต้องเชื่อม Facebook Login, Graph API หรือ Messenger API

หมายเหตุการตรวจสอบ: เครื่องมืออ่านหน้าเว็บไม่สามารถดึงเนื้อหาโปรไฟล์นี้ได้ จึงใช้ URL ตามที่ผู้ใช้ให้มา และยังต้องทดสอบการเปิดจริงบนมือถือและเดสก์ท็อป

### 6.4 เป้าหมาย: เปิด Messenger ส่วนตัวพร้อมรายการที่ลูกค้าเลือก

ใช้ Facebook ส่วนตัวของผู้ขายเป็นปลายทางติดต่อซื้อทั้งหมดตามที่เจ้าของร้านกำหนด การมีเพจ Clicko.gg ไม่เปลี่ยนขอบเขตนี้

ขั้นตอนที่วางแผนให้พัฒนาได้ในขณะนี้:

1. ลูกค้าเลือกสินค้า SKU และจำนวน
2. เว็บไซต์ตรวจข้อมูลสินค้าและสร้างข้อความสรุปพร้อมชื่อรุ่น SKU จำนวน ราคาที่แสดง และลิงก์สินค้า
3. ลูกค้ากดคัดลอกข้อความ และเว็บไซต์แจ้งผลตามที่คัดลอกได้จริง
4. ลูกค้ากดเปิด Messenger ส่วนตัวของผู้ขาย เมื่อมี URL ที่ยืนยันแล้ว
5. ลูกค้าวางข้อความและกดส่ง ผู้ขายตรวจราคา สต็อก และค่าส่งก่อนตกลงซื้อขาย

ระหว่างที่ยังไม่ยืนยันลิงก์แชท ให้เปิดโปรไฟล์ส่วนตัวเป็นทางสำรอง โดยไม่เปลี่ยนไปใช้แชทเพจ

ข้อกำหนดและข้อจำกัด:

- เป้าหมายที่อยากให้ข้อมูลสินค้าปรากฏในแชทส่วนตัวอัตโนมัติยังต้องตรวจสอบความเป็นไปได้ ไม่ถือว่าเป็นความสามารถที่รับรองแล้ว
- ยังไม่ยืนยันว่าการเติม `?text=` หรือพารามิเตอร์ข้อความลงใน URL โปรไฟล์หรือ Messenger ของบัญชีนี้ทำงานตามที่ต้องการ
- ไม่เปิดใช้ระบบ referral, webhook หรือบอตของเพจ และไม่นำรายการสอบถามไปยังกล่องข้อความเพจ
- ไม่สร้าง URL แชทส่วนตัวจากชื่อบัญชีโดยถือว่าทำงานแล้ว ต้องทดสอบกับบัญชีผู้ซื้อจริงก่อนตั้งค่าใช้งาน
- คงปุ่มคัดลอกและข้อความที่เลือกคัดลอกเองได้ เพื่อให้ส่งรายละเอียดครบแม้ไม่สามารถแนบอัตโนมัติ
- ไม่อ้างว่าส่งข้อความแล้วจากการกดลิงก์ และไม่ส่งข้อความแทนลูกค้า
- ทดสอบมือถือ เดสก์ท็อป และบัญชีที่ยังไม่เคยคุยกับผู้ขาย รวมถึงกรณีต้องเข้าสู่ระบบก่อน
- การคลิกไม่สร้างคำสั่งซื้อ ไม่จองสินค้า และไม่ตัดสต็อก
- ลิงก์ “ติดตามเพจ Clicko” เป็นลิงก์แยกสำหรับดูเพจ ไม่รับหน้าที่ส่งต่อรายการสินค้า

แนวทางใช้ Messenger ของเพจพร้อมระบบรับบริบทที่เคยเสนอถูกนำออกจากขอบเขตตามข้อกำหนดล่าสุดของเจ้าของร้าน

- เริ่มจากสถานะสินค้าที่ร้านอัปเดตเอง ไม่ต้องทำระบบคลังสินค้าเต็มรูปแบบ
- เมื่อมีการขายผ่าน Facebook หรือช่องทางอื่น ร้านต้องอัปเดตแค็ตตาล็อกให้สอดคล้อง
- การกดติดต่อซื้อไม่ตัดสต็อก ไม่จองสินค้า และไม่สร้างออเดอร์อัตโนมัติ
- หากเปิดแสดงจำนวนคงเหลือ ต้องกำหนดว่าใครดูแลและอัปเดตเมื่อใด
- บันทึกประวัติการแก้ราคา สถานะสินค้า และ URL ช่องทางขาย
- ยอดขายจริงยืนยันจากกระบวนการของร้าน ไม่อนุมานจากจำนวนคลิก

แยกธีมกับปลั๊กอินของ Clicko เพื่อให้การปรับหน้าตาไม่ปะปนกับกฎปุ่มติดต่อสินค้า เก็บ source code ของธีมและปลั๊กอินไว้ใน Git ส่วนผู้ขายใช้งานผ่าน Dashboard ตามปกติ ไม่แก้โค้ด

### 8.3 ขอบเขตงานที่ต้องทำครั้งเดียว

- ทำธีมและวางรูปแบบหน้าสินค้า หน้าแรก และหน้ามือถือให้เรียบร้อย
- เพิ่มช่องตั้งค่า Clicko สำหรับลิงก์ผู้ขาย Messenger ส่วนตัว ลิงก์โปรไฟล์สำรอง ลิงก์เพจ และข้อความปุ่ม
- เพิ่มปุ่มคัดลอกข้อความสินค้าและปุ่มเปิด Messenger/โปรไฟล์ผู้ขายตาม URL ที่ตั้งค่า
- ซ่อนส่วน checkout, cart และขั้นตอนชำระเงินที่ร้านไม่ได้ใช้
- กำหนดฟิลด์ที่ผู้ขายแก้ได้ และล็อกส่วนโครงสร้างที่อาจทำ layout เสีย
- ตั้งค่าแบ็กอัปและการอัปเดตผ่าน Managed WordPress Hosting
- ฝึกผู้ขายและส่งคู่มือภาษาไทยก่อนส่งมอบ

ผู้พัฒนาอาจต้องใช้โค้ดสร้างหน้าร้านและแบบฟอร์มผู้ดูแลครั้งแรก แต่หลังส่งมอบ ผู้ขายทำงานประจำ เช่น เพิ่มสินค้า แก้รูป/ราคา เปลี่ยนเนื้อหา และแก้ช่องทาง Facebook ได้จากหน้า Dashboard

### 8.4 หลักการเลือกปลั๊กอินและโฮสต์

- เลือก Managed WordPress Hosting ที่มี SSL, staging, สำรองข้อมูล และวิธีกู้คืนชัดเจน
- ใช้ปลั๊กอินเท่าที่จำเป็น เช่น WooCommerce และเครื่องมือที่เพิ่มช่องตั้งค่าหรือคุณลักษณะสินค้าที่ธีมหลักทำไม่ได้
- หลีกเลี่ยง page builder หลายตัวและปลั๊กอินซ้ำหน้าที่ เพราะเพิ่มภาระอัปเดตและทำให้ผู้ขายสับสน
- ตั้งสิทธิ์ผู้ขายให้แก้สินค้า/เนื้อหาได้ แต่ไม่ให้ลบปลั๊กอินหรือเปลี่ยนค่าระบบโดยไม่ตั้งใจ
- ทดสอบการอัปเดตบน staging ก่อน production หากบริการโฮสต์รองรับ
- ไม่มีระบบใดที่แก้ “ทุกอย่าง” โดยไม่ต้องดูแลเลย: เนื้อหาและข้อมูลแก้ได้เอง แต่การอัปเดต/สำรองระบบต้องมีคนหรือบริการโฮสต์รับผิดชอบ

## 9. ข้อมูลหลักในฐานข้อมูล

แนวคิดข้อมูลด้านล่างเป็นข้อมูลที่ต้องจัดการในแค็ตตาล็อก สำหรับ WordPress/WooCommerce ให้ใช้ product, variation, category, attribute, media และ page ของระบบก่อน ไม่ต้องสร้างฐานข้อมูลหรือตารางเองในเวอร์ชันแรก

| ข้อมูลในระบบ | ที่เก็บ/จุดแก้ใน Dashboard |
| --- | --- |
| ผู้ดูแล | Users และ roles ของ WordPress |
| สินค้าและ SKU | WooCommerce Products และ Product Variations |
| รูปและสื่อ | WordPress Media Library |
| หมวดและคุณลักษณะ | Product Categories และ Attributes |
| แบนเนอร์และหน้าเนื้อหา | WordPress Pages และตัวแก้ไขบล็อก |
| ช่องทางขายและข้อความ | ฟิลด์ตั้งค่า Clicko ใน Dashboard |

- SKU ไม่ซ้ำ และสินค้าที่มีตัวเลือกใช้ product variation
- ราคาไม่มีค่าต้องแยกจากราคาศูนย์บาทอย่างชัดเจน
- สินค้าซ่อนหรือหมดไม่ควรถูกเพิ่มใหม่ในรายการที่สนใจ
- สินค้าที่หมดสามารถคงหน้าเดิมเพื่อแสดงรายละเอียดและเสนอให้สอบถามได้
- ยังไม่ต้องเปิดตาราง/โมดูลลูกค้า ออเดอร์ การรับเงิน สลิป และข้อมูลจัดส่ง เพราะตกลงซื้อขายภายนอกเว็บ
- รายการที่สนใจอยู่ฝั่งลูกค้า ไม่ต้องสร้างตารางตะกร้าในระยะแรก

## 11. SEO และประสิทธิภาพ

- แต่ละสินค้าและหมวดมี URL ถาวร ชื่อหน้า และคำอธิบายเฉพาะ
- มีข้อมูลสินค้าหลักใน HTML ที่ระบบค้นหาอ่านได้
- จัดทำ sitemap และนโยบาย canonical สำหรับตัวกรอง
- ไม่ทำดัชนีหลังบ้านหรือหน้ารายการที่สนใจ และควบคุมสิทธิ์หลังบ้านแยกต่างหาก
- ใช้ Product structured data เฉพาะข้อมูลจริง ไม่สร้างราคา offer สำหรับสินค้าที่ต้องสอบถามราคา
- ปรับขนาดรูปและส่งตามขนาดหน้าจอ พร้อม lazy loading สำหรับรูปนอกจอ
- เมื่อแก้ราคา สถานะ หรือ URL Facebook ต้องมีวิธีอัปเดต cache
- โหลดราคาและสถานะล่าสุดอีกครั้งก่อนสร้างข้อความสรุป

- เปรียบเทียบสเปกและรายการแนะนำ หากมีความต้องการ

- [เพจ Clicko.gg ที่ผู้ใช้กำหนด](https://www.facebook.com/Clicko.gg/) — ใช้สำหรับลิงก์แบรนด์และข่าวสาร ตามขอบเขตที่ผู้ใช้ยืนยัน ไม่ใช้รับซื้อขายบนเว็บไซต์
