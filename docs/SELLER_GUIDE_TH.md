# คู่มือผู้ขาย Clicko

ผู้ขายจัดการแค็ตตาล็อกจากหน้า Admin ที่เชื่อม Supabase โดยไม่ต้องเปิดหรือแก้ไฟล์โค้ด

## เพิ่มสินค้า

1. เปิด `clicko-store.github.io/admin.html` แล้วเข้าสู่ระบบบัญชีผู้ดูแล/พนักงานที่ได้รับสิทธิ์
2. กด **เพิ่มสินค้าใหม่** แล้วกรอก SKU, ชื่อ, หมวดหมู่, สภาพ, ราคา, ประกัน และสเปก
3. อัปโหลดรูปสินค้า แล้วกด **บันทึกสินค้า**
4. ตรวจสินค้าในหน้า `/products/` บนมือถือ

ขณะนี้เพิ่มหรือแก้สินค้าได้ทีละรายการผ่านแบบฟอร์ม Admin ยังไม่มีระบบนำเข้าสินค้าจาก CSV/Excel อัตโนมัติ

## บัญชีลูกค้าและบัญชีร้าน

- ลูกค้าเข้าดูสินค้าและติดต่อร้านได้โดยไม่ต้อง login; หน้า `/account/` เป็นทางเลือกสำหรับสมัคร/เข้าสู่ระบบและบันทึกโปรไฟล์ลูกค้า
- เจ้าของร้าน/พนักงานจัดการสินค้าที่ `clicko-store.github.io/admin.html` ด้วยบัญชี Supabase Auth ที่ถูกเพิ่มใน `clicko_admins` หรือ `clicko_staff_members` เท่านั้น
- หน้า `/trade-in-admin/` ใช้บัญชี Supabase Auth เช่นกัน แต่สิทธิ์อ่านคำขอรับซื้อควบคุมด้วย RLS และรายการพนักงาน/ผู้ดูแล
- บัญชี WordPress ที่ `/wp-admin/` แยกจาก Supabase; ไม่ต้องสร้างบัญชี WordPress ให้ลูกค้าเพื่อให้ลูกค้าดูสินค้า

## แก้หน้าแรกและเนื้อหา

- เข้า **หน้า → หน้าแรก → แก้ไข** เพื่อแก้ข้อความและเพิ่ม/เปลี่ยนรูปผ่านตัวแก้ไขบล็อก
- เข้า **รูปลักษณ์ → ปรับแต่ง → Clicko homepage** เพื่อแก้คำโปรยและหัวเรื่อง
- เข้า **รูปลักษณ์ → ปรับแต่ง → Site Identity** เพื่อเปลี่ยนโลโก้และชื่อเว็บ
- เข้า **รูปลักษณ์ → เมนู** เพื่อจัดรายการเมนูหลัก
- แก้หน้าแรก สินค้าทั้งหมด ติดต่อ ประกัน และเงื่อนไขได้จาก **หน้า → ทุกหน้า**

เขียนรายละเอียดประกันและเงื่อนไขคืนสินค้าตามนโยบายจริงของร้านก่อนเผยแพร่

## เปลี่ยนช่องทาง Facebook

เข้า **Clicko** ที่เมนูด้านซ้ายของ Dashboard:

- **Facebook ส่วนตัวของผู้ขาย** เป็นปลายทางซื้อขายและลิงก์สำรอง
- **ลิงก์ Messenger ส่วนตัว** เว้นว่างไว้จนกว่าจะทดสอบว่าเปิดแชทถึงบัญชีผู้ขายได้จริง
- **เพจ Clicko** ใช้ติดตามข่าวสารและแสดงแบรนด์เท่านั้น
- ปรับข้อความขึ้นต้นและลงท้ายที่เว็บเตรียมให้ลูกค้าคัดลอกได้

การกดเปิด Facebook ไม่ได้ส่งข้อความให้อัตโนมัติ ลูกค้าต้องวางข้อความรายการสินค้าในแชทและกดส่งเอง ผู้ขายจึงยืนยันราคา สต็อก และค่าจัดส่งผ่านการพูดคุย

## รายการสินค้าที่สนใจ

ลูกค้าเพิ่มสินค้าในรายการได้จากการ์ดและหน้ารายละเอียดสินค้า รายการนี้เก็บในเบราว์เซอร์ของลูกค้า ไม่ใช่คำสั่งซื้อและไม่จองสินค้า เมื่อลูกค้าเปิดหน้า **รายการที่สนใจ** ระบบจะโหลดข้อมูลสินค้าและราคาปัจจุบันใหม่ก่อนสร้างข้อความ

## ก่อนปรับปรุงเว็บไซต์

- ตรวจว่าสินค้า รูป ราคา และสถานะพร้อมขายถูกต้อง
- สำรองเว็บไซต์และฐานข้อมูลก่อนอัปเดต WordPress หรือปลั๊กอิน
- หากโฮสต์มี staging ให้ทดสอบการอัปเดตก่อนใช้งานจริง
- หากปุ่ม Messenger เปิดผิดบัญชี ให้ลบ URL Messenger ในหน้า Clicko เพื่อกลับไปใช้ Facebook โปรไฟล์สำรอง

## บัญชีผู้ดูแลและพนักงาน

- ผู้ดูแลเชิญบัญชีพนักงานจาก Supabase **Authentication → Users** แล้วนำ Auth user UUID ไปเพิ่มใน `clicko_staff_members` ผ่าน SQL Editor ตามตัวอย่างในคู่มือฐานข้อมูล
- พนักงานจัดการสินค้าที่ `https://clicko-store.github.io/admin.html` ด้วยบัญชี Supabase ที่ได้รับอนุมัติ; `/store-dashboard/` เป็นทางเข้าจาก WordPress ไปยังเครื่องมือนี้
- สิทธิ์พนักงานจำกัดอยู่ที่แค็ตตาล็อกและรูปสินค้า ไม่ครอบคลุมโปรไฟล์สมาชิก ต้นทุน หรือคำสั่งซื้อ
- ลูกค้าสมัครและเข้าสู่ระบบด้วยอีเมลหรือ Facebook ได้ที่ `/account/`; ข้อมูลโปรไฟล์อยู่ใน Supabase ส่วนตัวตนและอีเมลล็อกอินอยู่ใน Supabase Auth
- Facebook Login ต้องตั้ง Facebook App ID/Secret, callback URL และ allowed redirect URLs ใน Supabase Dashboard ก่อนเปิดใช้กับลูกค้าจริง

## รับซื้อ / เทิร์นอุปกรณ์

- หน้า `/trade-in/` ให้ลูกค้ากรอกรุ่น ประกัน สภาพ และอัปโหลดรูป JPG/PNG/WEBP ได้สูงสุด 4 รูป (รูปละไม่เกิน 5 MB)
- เมื่อส่งแล้ว Edge Function ตรวจข้อมูลและ Turnstile ก่อนจัดเก็บคำขอใน `clicko_trade_inquiries` และรูปใน private bucket `clicko-trade-in-photos`
- ผู้ดูแลและพนักงานที่ได้รับสิทธิ์เปิด `/trade-in-admin/` ด้วยบัญชี Supabase เพื่อดูรายละเอียด รูป และปรับสถานะคำขอ
- ข้อมูลฟอร์มนี้ยังไม่แจ้งเตือนไปยัง Facebook ส่วนตัวของ Kew; Meta ไม่มี API สำหรับเว็บส่งข้อความใหม่เข้า Inbox ส่วนตัวโดยอัตโนมัติ ต้องใช้แดชบอร์ดหรือช่องทางแจ้งเตือนอื่นแทน
- ตั้งค่า Edge Function, Cloudflare Turnstile และระยะเวลาเก็บ/ลบคำขอก่อนเปิดฟอร์มจริง ดูขั้นตอนใน `docs/TRADE_IN_INTAKE.md`

## ย้ายสินค้าจากระบบเดิม

สินค้าใน Supabase เป็นข้อมูลหลัก หน้าแรกอ่านจาก `clicko_products`; ห้ามแก้ WooCommerce แล้วคาดว่าข้อมูลจะ sync กลับโดยอัตโนมัติ อย่าใช้ fixture ในไฟล์หน้าเว็บแทนข้อมูลปัจจุบัน และอย่านำออเดอร์เดิมเข้าเป็น WooCommerce order ที่ดูเหมือนชำระเงินแล้วโดยไม่ตรวจสอบ
